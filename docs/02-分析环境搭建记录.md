# 02｜分析环境搭建记录

本文记录之前为本机大肥鱼分析准备的工具。路径来自此前配置记录，若电脑环境有变化，应重新检查。

## 1. REA 是什么？

REA 是一套程序分析工具和 MCP 服务。可以把它理解成“让 AI 能够调用的一组本地分析工具”。它能帮助检查二进制文件、程序结构、函数和反汇编等内容。

### 本机安装位置

- REA 根目录：`C:\Users\23209\.dsh\rea-runtime`
- REA 命令：`C:\Users\23209\.dsh\rea-runtime\npm-global\rea.cmd`
- REA 包：`C:\Users\23209\.dsh\rea-runtime\npm-global\node_modules\rea-agents`

此前记录的 REA CLI 版本：6.10.1。

## 2. Node.js

- 版本：26.12.1
- 目录：`C:\Users\23209\.dsh\rea-runtime\node\node-v26.12.1-win-x64`

REA CLI 需要 Node.js 版本至少为 26.12.1。启动 REA 时，应优先把这个版本的目录放到 PATH 前面，避免误用电脑上其他旧版本。

## 3. Java 和 Ghidra

- Java：JDK 25.0.5.1+2
- Java 目录：`C:\Users\23209\.dsh\rea-runtime\jdk25\jdk-25.0.5.1+2`
- Ghidra：12.2
- Ghidra 目录：`C:\Users\23209\.dsh\rea-runtime\ghidra\ghidra_12.2_PUBLIC`

Ghidra 是 NSA 发布的程序逆向分析工具。它可以把机器码转换成更容易阅读的反汇编和伪 C 代码，帮助分析 EXE 内部函数。

注意：REA 是否真正加载了 Ghidra，不能只看文件夹存在。必须检查 REA 的 Provider 状态，并实际执行一个分析操作确认。

## 4. JADX

- JAR：`C:\Users\23209\.dsh\rea-runtime\jadx\jadx-headless-mcp-0.7.1-all.jar`

JADX 主要用于 Android / DEX / APK 分析。它不是分析普通 Windows Electron EXE 的首选工具；记录它只是因为它曾被安装在同一套工具环境中。

## 5. REA MCP 服务

此前配置记录：

- REA MCP 地址：`http://127.0.0.1:8765/mcp`
- 仅监听本机回环地址 `127.0.0.1`
- Windows 计划任务名称：`REA Local MCP`
- 启动脚本：`C:\Users\23209\.dsh\profiles\desktop\scripts\start-rea-server.ps1`

本机回环地址意味着服务只对这台电脑本机开放，不应该为了方便而把没有鉴权的 MCP 服务直接暴露到公网。

## 6. 本地代理（Tailscale 用途）

此前还配置过：

- 代理脚本：`C:\Users\23209\.dsh\profiles\desktop\scripts\rea-mcp-proxy.cjs`
- 代理监听：`127.0.0.1:8766`
- 转发到：`127.0.0.1:8765`

这个代理主要用于 Tailscale Serve。它和 OpenAI Secure MCP Tunnel 是两条不同的连接路线，不要把它们混为一谈。

## 7. 如何检查环境

建议在 PowerShell 中逐项检查（以下是检查示例，路径以本机实际情况为准）：

```powershell
& 'C:\Users\23209\.dsh\rea-runtime\npm-global\rea.cmd' --version
& 'C:\Users\23209\.dsh\rea-runtime\node\node-v26.12.1-win-x64\node.exe' --version
Test-Path 'C:\Users\23209\.dsh\rea-runtime\ghidra\ghidra_12.2_PUBLIC'
Test-Path 'C:\Users\23209\.dsh\rea-runtime\jdk25\jdk-25.0.5.1+2'
Test-NetConnection 127.0.0.1 -Port 8765
```

检查命令只用于读取状态，不会修改程序。

## 8. 重要提醒

本文件记录的是安装路径和版本信息，不是完整安装包。不要把 Node、JDK、Ghidra、REA 的整个目录上传到 GitHub；它们体积大，而且通常有各自的许可证和更新机制。
