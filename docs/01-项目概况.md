# 01｜大肥鱼项目概况

## 1. 我们在研究什么？

目前要研究的是 Windows 上的大肥鱼桌面应用（主程序名称为 DeepSeek Harness）。用户希望借助 REA 等逆向分析工具，逐步弄清楚程序内部结构和功能实现，尤其关注：

1. 桌宠：角色如何显示、如何动、如何响应鼠标和用户操作。
2. QQ 语音：程序是否有发起或控制 QQ 语音通话的代码，具体通过什么方式实现。
3. 会话管理：聊天会话如何创建、保存、恢复，之前遇到的会话不显示问题可能与什么有关。
4. 语音能力：本地语音服务如何启动、如何通信、如何把声音送进应用。
5. Electron 内部结构：主进程、渲染进程、IPC、应用资源和原生模块之间如何配合。

这些是研究目标，不代表这些功能已经被证实存在或已经修好。

## 2. 主程序位置

- 主程序：`G:\big_blue_fish\DeepSeek Harness.exe`
- 所在目录：`G:\big_blue_fish`

这是用户电脑上的实际路径。不要把它当成仓库里的相对路径，也不要假设其他电脑有 G 盘。

## 3. 分析目标是什么？

不要只盯着 EXE 文件本身。桌面软件经常把大量业务逻辑放在旁边的资源文件中。若它使用 Electron，常见结构是：

- EXE：负责启动桌面运行环境。
- Electron / Chromium：负责窗口、网页渲染和底层运行。
- Node.js：让桌面应用可以执行 JavaScript 并访问本机能力。
- 应用资源（例如 app.asar）：可能包含真正的页面和业务逻辑。
- 原生模块 / 外部程序：提供音频、视频、系统操作等能力。

以上是 Electron 应用的常见工作方式。**是否与当前版本完全一致，需要检查实际文件来确认。**

## 4. 我们最终想得到什么？

不是一份看起来很专业但无法验证的报告，而是一套能实际用于后续维护的资料：

- 程序目录结构图
- 关键文件说明
- 桌宠从启动到显示的调用流程
- QQ 语音相关功能的真实调用流程（如果存在）
- 会话保存和恢复流程
- 本地语音服务的启动和通信流程
- 可重复执行的检查命令
- 每次修改前后的备份和验证步骤

## 5. 分析边界

优先做静态分析（查看文件、字符串、依赖、代码结构），必要时再做动态分析（运行程序并观察行为）。不绕过账号权限、不窃取凭据、不对第三方服务进行未授权操作。对程序做修改前先备份。
