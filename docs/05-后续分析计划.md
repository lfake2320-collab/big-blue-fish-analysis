# 05｜后续分析计划（按顺序来）

## 第一步：重新确认目标文件

检查文件是否存在、大小、修改时间和 SHA-256。这样可以确认现在分析的是哪一版程序。

PowerShell 示例：

```powershell
$exe = 'G:\big_blue_fish\DeepSeek Harness.exe'
Get-Item $exe | Select-Object FullName, Length, LastWriteTime
Get-FileHash $exe -Algorithm SHA256
```

如果路径不存在，先找回正确路径，不要猜测或自行替换目标。

## 第二步：确认 REA 和 Ghidra Provider

1. 检查 REA 服务是否运行。
2. 查看 REA Provider 列表。
3. 确认 Ghidra 12.2 路径和 Java 路径。
4. 通过 REA 打开 EXE。
5. 执行最基础的二进制信息、入口点、节区和导入表检查。
6. 记录工具的真实返回结果。

如果 Ghidra 失败，先解决环境配置，不要把失败说成分析成功。

## 第三步：分析 Electron 资源

如果程序中确实有 `resources\app.asar`：

1. 先记录 ASAR 文件大小和哈希。
2. 查看 ASAR 内部文件列表。
3. 找到 package.json、主进程入口、渲染进程入口。
4. 搜索 IPC 注册和调用。
5. 先阅读相关代码，不要直接修改原始文件。
6. 把重要文件路径和关键代码位置写入报告。

解包时使用副本，保留原始 ASAR 不动。

## 第四步：按功能追踪

### 桌宠

从“应用启动”开始追：创建窗口 → 加载页面 → 创建角色 → 加载模型/图片 → 播放动画 → 接收鼠标和消息。

需要找到实际代码和资源文件才能确认每一步。

### QQ 语音

先搜索 QQ、语音通话、窗口标题、进程名、按键、音频设备等相关关键词。随后追踪调用者和调用目标。重点确认是否有真正的通话控制流程，而不是只有普通音频播放或录音。

### 会话管理

搜索 session、conversation、workspace、history、storage 等关键词。确认：
- 会话 ID 在哪里生成？
- 文件保存在哪里？
- 启动时从哪里加载？
- 工作区路径如何计算？
- 路径不存在时会怎样？
- 文件夹改名后是否会导致索引失效？

### 语音服务

搜索 TTS、ASR、speech、audio、voice、gpt-sovits 等关键词。确认服务如何启动、端口如何分配、数据如何传输，以及服务退出后应用如何处理。

## 第五步：每次修改都先备份

如果最终需要修复大肥鱼：
1. 复制原文件到备份目录。
2. 记录修改前哈希。
3. 一次只改一个问题。
4. 启动应用验证。
5. 记录修改后的差异和结果。
6. 失败时恢复备份。

不要直接在唯一一份原始程序上试错。

## 当前优先级

1. **最高：**让 REA + Ghidra 对主 EXE 成功完成一次实际分析。
2. **最高：**取得 app.asar 文件清单和应用入口。
3. **高：**先追踪会话管理，因为它与此前“没有会话”的问题直接相关。
4. **高：**追踪桌宠的渲染方式。
5. **中：**追踪 QQ 语音和本地语音服务。

每完成一项，就更新本仓库对应文档。
